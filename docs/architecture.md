# Архитектура

Сервер создаёт самостоятельную runtime-копию подготовленного примера. Его корень вычисляется относительно src/server.js, а не текущего каталога терминала.

```text
courses/                 Версионируемое содержание примера, без личного прогресса
src/domain/              Схемы, состояния и переходы обучения
src/application/         Сеансы курсов, блокировки операций, сборники
src/content/             Каталог, загрузка пакетов, проверка вложений
src/persistence/         Markdown-память курсов, JSON-навигация
src/http/                API и безопасная выдача вложений
src/ai/                  Необязательные адаптеры и контракты ответов
public/                  Интерфейс без сборки
scripts/                 Проверка содержания, создание новой памяти, HTTP smoke
.local/runtime/          Изменяемый прогресс, не входит в Git
```

Состояния видеоглавы: вопрос -> разбор ответа -> следующий вопрос -> следующая глава. В главе три вопроса. Пропуск вопросов записывается отдельно, режим без вопросов не подменяет правильные ответы. После завершения доступен просмотр пройденного материала.

Память курса записывается атомарно: временный файл заменяет исходный. Операции одного курса сериализуются. Позиция просмотра сохраняется отдельно от ответов; изменение позиции само по себе не является сдачей теста.

Встроенный плеер остаётся смонтированным при ответах на вопросы той же главы. При смене главы он закрывается и создаётся для нового временного интервала. Нельзя скрывать брендинг или подменять управление YouTube.

Здесь также сохранён движок текстовых материалов и сборников из исходной системы. В стартовую библиотеку включён только согласованный видеокурс. Состояния других людей и учебные материалы источника не переносились.

Обновлять пакет после начала работы нужно с учётом contentVersion. Стартовый код отказывается заменять изменившийся пакет в существующем runtime без миграции. Каталог runtime может отличаться от исходного из-за архивирования, это не сбрасывает содержимое курса.
